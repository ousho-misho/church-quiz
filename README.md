# مسابقة درس الكتاب — نسخة أوفلاين 100% (بدعم PWA / Service Worker)

تطبيق ويب بسيط (HTML/CSS/JavaScript فقط) لعمل مسابقة كتابية داخل الكنيسة، ويعمل بالكامل **بدون إنترنت** — بما في ذلك عند نشره على GitHub Pages وفتحه لاحقًا بدون اتصال.

## هيكل المشروع

```text
project/
│
├── index.html          ← الصفحة الرئيسية (نفس الأسئلة والتصميم والمنطق، بدون أي تغيير)
├── service-worker.js    ← جديد: يخزّن الملفات ويجعل الموقع يعمل أوفلاين بعد أول زيارة أونلاين
├── manifest.json        ← جديد: ملف PWA (اسم التطبيق، الأيقونة، الألوان)
├── images/
│   └── church-logo.jpg ← شعار الخدمة (محلي بالكامل)
├── js/
│   └── qrcode.min.js   ← مكتبة توليد QR Code محليًا (بدون CDN) — لم تُستبدل ولم تُعدَّل
└── README.md
```

**تنبيه:** بعد فك ضغط أي ملف مضغوط، تأكد أن الأسماء والمسارات مطابقة تمامًا لما سبق (`images/church-logo.jpg` و`js/qrcode.min.js`)، وإلا فلن تعمل الصور ورمز الـ QR ولا التخزين المؤقت.

## ما الجديد: دعم العمل أوفلاين على GitHub Pages (Service Worker)

المشكلة السابقة: فتح المسابقة أوفلاين كان يعمل فقط عند تشغيل `index.html` مباشرة من جهاز الكمبيوتر. أما رابط GitHub Pages نفسه فكان يظهر `ERR_INTERNET_DISCONNECTED` لأن المتصفح لم يكن يخزّن أي شيء من الموقع.

**تم الحل بإضافة Service Worker حقيقي:**

1. `manifest.json` — يصف التطبيق (اسمه، أيقونته، ألوانه) باستخدام مسارات نسبية (`./`) فقط، حتى يعمل سواء كان الموقع على:
   - `https://username.github.io/` (جذر الدومين)، أو
   - `https://username.github.io/REPO/` (مسار فرعي داخل مشروع) — وهي الحالة الشائعة في GitHub Pages.

2. `service-worker.js` — يُسجَّل من `index.html` عبر مسار نسبي (`./service-worker.js`)، وبالتالي يأخذ تلقائيًا نطاق (scope) مطابق لمجلد الموقع الفعلي مهما كان مساره.
   - عند أول زيارة **أونلاين**: يخزّن هذه الملفات في الكاش:
     `./` , `./index.html` , `./manifest.json` , `./images/church-logo.jpg` , `./js/qrcode.min.js`
   - عند أي زيارة لاحقة (أونلاين أو أوفلاين): يستخدم استراتيجية "الكاش أولاً" (Cache First) لكل الملفات الثابتة، وللتنقل بين الصفحات (Navigation) يحاول الشبكة أولاً ثم يرجع فورًا لنسخة `index.html` المخزَّنة إن لم يوجد إنترنت.
   - لا يعتمد على أي CDN أو خط خارجي أو خدمة خارجية — كل شيء محلي 100%، تمامًا كباقي المشروع.

3. `index.html` — أُضيف له فقط:
   - وسم `<link rel="manifest" href="./manifest.json">` وأيقونة الصفحة (favicon) من نفس اللوجو.
   - سكريبت صغير منفصل تمامًا في نهاية الصفحة يسجّل `service-worker.js` عند تحميل الصفحة.
   - رسالة صغيرة اختيارية غير إلزامية تظهر لثوانٍ بعد اكتمال التخزين: **"تم تجهيز المسابقة للعمل بدون إنترنت"**.
   - **لم يتم تغيير أي شيء آخر**: نفس الأسئلة، نفس منطق التصحيح، نفس توليد QR Code، نفس التصميم، نفس المؤقت.

## طريقة الاختبار (بدون إنترنت) على الجهاز المحلي

1. افتح ملف `index.html` مباشرة، أو شغّله عبر خادم محلي بسيط.
2. تأكد أن الشعار يظهر أعلى الصفحة، وأن المؤقت يبدأ العد التنازلي من 02:00.
3. أجب عن الأسئلة واضغط "إنهاء واستخراج الـ QR Code"، وتأكد من ظهور رمز الـ QR فورًا.
4. اضغط "بدء مسابقة جديدة" وتأكد من إعادة التعيين الكاملة دون تكرار المؤقت.

## طريقة اختبار العمل أوفلاين عبر GitHub Pages (السيناريو الفعلي المطلوب)

1. ارفع محتويات مجلد `project/` (وليس المجلد نفسه) إلى جذر المستودع، وفعّل GitHub Pages.
2. افتح رابط GitHub Pages **والإنترنت متصل**، وانتظر تحميل الصفحة بالكامل (تظهر رسالة "تم تجهيز المسابقة للعمل بدون إنترنت" لثوانٍ قليلة، وهذا مؤشر أن التخزين اكتمل).
3. أعد تحميل الصفحة مرة واحدة على الأقل وأنت لا تزال متصلاً (لضمان أن Service Worker أصبح نشطًا ومتحكمًا في الصفحة).
4. اقطع الإنترنت بالكامل (Wi-Fi وبيانات الجوال، أو وضع الطيران).
5. أغلق التبويب.
6. افتح نفس رابط GitHub Pages مرة أخرى.
7. يجب أن تُحمَّل المسابقة بالكامل، ويظهر الشعار، ويعمل المؤقت، دون ظهور `ERR_INTERNET_DISCONNECTED`.
8. أكمل الإجابة على الأسئلة، وتأكد من ظهور رمز الـ QR بشكل طبيعي.
9. امسح رمز الـ QR وتأكد أن النتيجة العربية (الاسم، المرحلة، الدرجة، كل الإجابات) صحيحة ومطابقة.

### تم اختبار هذا التدفق فعليًا (وليس نظريًا)

تم تشغيل هذا السيناريو بالضبط باستخدام متصفح Chromium حقيقي (عبر Playwright)، مع محاكاة استضافة المشروع تحت مسار فرعي يُحاكي بنية GitHub Pages الفعلية (`https://.../REPO/`) وليس جذر الدومين، وباستخدام ملف تعريف متصفح (profile) دائم لمحاكاة إغلاق التبويب وإعادة فتحه بشكل حقيقي:

- **الزيارة الأولى (أونلاين):** تم تحميل الصفحة، والتأكد من أن Service Worker تفعّل (`activated`) وأصبح متحكمًا في الصفحة (`controller`)، والتحقق من أن كل الملفات المطلوبة (`index.html`, `manifest.json`, الشعار, `qrcode.min.js`) موجودة فعليًا داخل الـ Cache Storage.
- **إغلاق المتصفح بالكامل، ثم إعادة فتحه من نفس ملف التعريف مع تعطيل الشبكة تمامًا (`offline: true`)، والانتقال لنفس الرابط:**
  - لم تظهر `ERR_INTERNET_DISCONNECTED`.
  - ظهر عنوان الصفحة والشعار بشكل طبيعي.
  - المؤقت بدأ من 02:00 كالمعتاد.
  - لم يتم إرسال أي طلب شبكة جديد إلى الخادم أثناء هذه المرحلة (تم التأكد من ذلك من سجلات الخادم)، مما يثبت أن كل شيء جاء من الكاش فقط.
  - تم ملء بيانات عربية حقيقية والإجابة على الأسئلة (بإجابة خاطئة واحدة عمدًا)، وتم توليد رمز QR بنجاح بدون إنترنت.
  - تم فك تشفير رمز الـ QR فعليًا بعد ذلك، وتطابق النص المستخرج تمامًا مع الاسم والمرحلة والدرجة الصحيحة (٤/٥) وكل الإجابات المُدخلة.

هذا يثبت أن التخزين المؤقت والعمل بدون إنترنت يعملان فعليًا تحت مسار فرعي شبيه بمسار GitHub Pages الحقيقي، وليس فقط على جذر الدومين.

## النشر على GitHub Pages

المشروع يستخدم مسارات نسبية فقط في كل مكان (`./index.html`, `./images/...`, `./js/...`, `./manifest.json`, `./service-worker.js`)، ولا يفترض أبدًا أن الموقع على جذر الدومين. لذلك يعمل بشكل صحيح سواء تم نشره على:

- `https://username.github.io/` (Pages على مستوى الحساب)، أو
- `https://username.github.io/REPO/` (Pages على مستوى مستودع/مشروع) — وهي الحالة الأكثر شيوعًا.

نطاق (scope) الـ Service Worker يُحدَّد تلقائيًا بناءً على مكان `service-worker.js` نفسه، دون أي إعداد إضافي.

## ملاحظات هامة

- لم يتم تغيير أي شيء في الأسئلة أو منطق التصحيح أو توليد QR Code أو الشعار أو التصميم — الإضافات الوحيدة هي دعم PWA/Service Worker (3 ملفات/تعديلات محددة كما هو موضح أعلاه).
- لا يعتمد المشروع على React أو Next.js أو أي خادم خلفي (backend) أو قاعدة بيانات أو API أو CDN خارجي أو خطوط خارجية أو خدمة QR خارجية. كل شيء يعمل من جهة العميل (Client-side) بالكامل.
- إذا احتجت تحديث أي ملف من ملفات المشروع مستقبلاً (مثلاً تعديل سؤال)، غيّر رقم النسخة `CACHE_VERSION` داخل `service-worker.js` حتى يقوم المتصفح باستبدال النسخة القديمة المخزَّنة بالنسخة الجديدة عند أول زيارة أونلاين تالية.
